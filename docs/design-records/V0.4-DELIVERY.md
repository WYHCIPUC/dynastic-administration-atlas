## 三、compose 全栈本地验证

**凭据纪律**：ADMIN_EMAIL / ADMIN_PASSWORD_HASH（argon2id，经 web 依赖 argon2 现场生成）/ ADMIN_SESSION_SECRET 全部随机生成，仅写入根目录 `.env`（compose 变量注入）与系统临时目录明文口令（测试后删除）；源码、示例、compose 文件中无任何可用凭据字面量。

**修复与工作around（记录在案）**：
1. 新增 `web/.dockerignore`（node_modules/.next/env/tests 等）——此前缺失会导致 builder 阶段 `COPY . .` 用宿主 Windows node_modules 覆盖 deps 阶段的容器 node_modules（含原生模块，属构建必坏点）。
2. `node:22-alpine` 基镜像 Docker Hub 直拉超时（与此前 postgres 同病）；docker.m.daocloud.io 当日亦停滞，最终经 dockerproxy.net 拉取后本地 tag。
3. 本机 3000 端口被无关容器（mirofish）占用：临时 `docker-compose.override.yml` 将 web 发布到 13000，验证后删除。

验证结果：`docker compose -p atlas up -d --build` —— **全链路通过**（image 构建成功；中途 3000 端口冲突一次，见 workaround 3，改 `!override` 后通过）。

- migrate（deploy + content:import）：**成功**。日志：「No pending migrations to apply」+「Imported 46 sources, 11 periods and 444 office examples」——P013–P015 随新 CSV 入库。
- web 容器健康（/api/health）：`{"status":"ok"}`；首页 `/` 200；/api/sources 返回注册表行（容器内 public/data 随 postbuild 复制正常）。
- 公共数据面（db 容器 psql 计数）：**Source 46 / Period 11 / Office 444**。
- 管理端登录冒烟（随机凭据，13000 端口）：错密 401；正密 200 且下发 `atlas_admin_session` + `atlas_admin_csrf` 双 cookie；`/api/admin/session` 携 cookie 返回 `authenticated:true` 与随机邮箱回显；`POST /api/admin/claims` 补齐 `x-csrf-token` 后空体返回 400（实体校验报错）——证明 鉴权→CSRF 双提交→业务校验 三层全通。
- **凭据注入坑（记录在案）**：argon2id 哈希中的 `$` 段（`$argon2id$v$m$t$p$salt`）会被 compose 对 `.env` 值做插值剥离，容器收到残串导致恒 401；修法为 `.env` 中 `$` 写作 `$$`（转义后容器内还原为单 `$`，已 exec env 验证）。
- **ports 合并坑（记录在案）**：override 文件的 `ports:` 列表对基础文件是**追加**而非替换，须用 `ports: !override` 才能去掉基础文件的 `3000:3000`。
- 收尾：`docker compose -p atlas rm -sf web migrate`（保留 db healthy 运行），删除 docker-compose.override.yml 与临时口令文件（%TEMP%）——已执行。
